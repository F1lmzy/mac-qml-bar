# Maccer launcher backends

## Implementation contract

The pill owns the window, focus and keyboard input. maccer supplies the provider registry, search coordinator, history, actions and native application icons through a Rust cdylib. GPUI is not linked. The shared-service native startup rule applies to both supplied frontends.

C ABI v1 with additive pixel accessors: `maccer_agent_create(bool fixture)`, `maccer_agent_destroy(handle)`, `maccer_agent_send(handle, const char *json)`, `maccer_agent_poll(handle)`, `maccer_agent_string_free(char *)`. Send returns null on acceptance or an owned error string. Poll returns null when empty or an owned UTF-8 JSON string. All handle calls are serialized on the Qt/macOS main thread. Destruction cancels work without waiting for workers that may be dispatching native actions to that thread. No worker holds a Qt pointer.

Requests: search {op, request, query}; activate {op, request, search_request, provider, id, action, confirmed?}; cancel {op}. Activation carries a new operation request ID and the request ID of the displayed result snapshot in search_request. `confirmed` defaults to false and must be set true only after the user explicitly confirms the descriptor's `confirmation` prompt. The frontend assigns monotonically increasing request IDs and ignores events from older requests. The backend retains authoritative result items and rejects arbitrary/stale item identities and unsupported actions. No item payload supplied by QML is trusted.

Events: ready {type, shortcutError}; results {type, request, items, complete, errors}; icon {type, request, provider, id, source}; outcome {type, request, kind, text?, title?, focusTransferred?}; error {type, request?, message}; toggle {type}. Item rows carry id, provider, title, subtitle, iconSource, iconText and actions [{id,title}]. Outcome kinds: close, keepOpen, setQuery, refresh, output. Provider-picker activation returns setQuery. Paste is unavailable until the previous-app target is integrated and verified.

## Application logos

maccer's app provider supplies an `ApplicationBundle` descriptor. The agent resolves it through `launcher_macos::application_icon_pixels`, the same AppKit-backed function used by maccer's GPUI frontend. Four background workers prepare top-to-bottom straight-alpha BGRA pixels, at most 64x64. Application logos never pass through PNG encoding, base64 or Qt image decoding.

A bounded 512-icon maccer cache survives searches and dismissal. Warm results already contain `iconSource: "image://maccer-icons/<token>"`; cold results receive a later icon event. Tokens are opaque, never reused within an agent, and stop resolving after eviction. Pending work is scoped to each search so an older query cannot strand a newer row without its icon. In-flight lookups may warm the cache after cancellation, but stale events cannot update current rows.

The additive C ABI `maccer_agent_icon(handle, token)` returns an owned `MaccerIconPixels` copy or null for missing/invalid tokens. It only reads cached pixels and never calls AppKit. Release it with `maccer_agent_icon_free(icon)`. Qt copies the pixels before freeing that allocation and displays them through a mutex-protected in-memory QQuickImageProvider. This display cache also survives queries and remains safe after service destruction. Neither the image-loading thread nor QML accesses the Rust handle. Existing PNG descriptors from other providers retain their data-URL route.

First-time or evicted logos still load asynchronously; this does not promise zero-latency cold AppKit resolution. Qt image-provider threading and source-size handling follow the [Qt image-provider contract](https://doc.qt.io/qt-6/qquickimageprovider.html).

## First slice and acceptance

- Fixed 480x380 launcher body uses the existing width/height/radius morph and PillSurface fade, with a scrollable result list.
- Search input uses Qt's native TextInput composition support, not GPUI input code.
- Apps, calculator, web, files and shell reuse maccer configuration and implementation. Clipboard capture/copy can use the existing provider, but paste is not exposed. Preview/drag are deferred.
- Arrow keys navigate, Return activates, Cmd-K opens actions, Tab invokes the secondary action, Cmd-P opens the provider picker. Escape unwinds actions/output, then query, then closes.
- The configured maccer shortcut opens/toggles the launcher. Registration conflicts must be visible; a clickable pill launcher entry remains available.
- Search and activation work never block the Qt render thread. New queries and dismissal cancel outstanding work. Native icons resolve lazily and separately from search.
- Fixture mode must not access hardware, clipboard, persistent history, hotkeys, network or application activation.
- Tests cover ABI ownership, cancellation/stale events, malformed/forged activation, keyboard navigation, Unicode text, launcher geometry, native focus/catcher lifecycle, and relocated-bundle linking. Real IME composition and real app activation remain manual checks unless explicitly exercised.

## Shared service opt-in

Set `MACCER_SERVICE_SOCKET` to an already-running Maccer service's absolute Unix socket path when launching a newly built Pill process:

```sh
MACCER_SERVICE_SOCKET=/tmp/maccer-service.REPLACE_ME/rpc ./scripts/run.sh --show-launcher
```

Start that service separately with `maccer-service --apps --socket PATH`. Its socket parent must already be private and owner-only. The service's `--apps` mode supplies Applications, Themes with confirmed Apply, configured Web Search, and backend-owned Clipboard history; its `--fixture` mode supplies the inert searchable menu with all eight planned provider categories. See the [Maccer service guide](https://github.com/F1lmzy/maccer/blob/main/docs/shared-service.md) for commands and limits.

With the environment set, `maccer_agent_connect_frontend(socket, "pill")` performs search IPC and independent frontend-control polling on background threads. Pill owns only presentation and the local pixel cache, not a Maccer registry, clipboard capture, hotkey registration or provider configuration. The native theme watcher/catalog/helper is not constructed in service mode. Other native hardware integrations remain unchanged. Live service mode supplies configured Applications, Themes, Web Search and Clipboard providers. Web Search preserves the configured default engine and prefix. Clipboard history is shared with GPUI and continues capturing while Pill is closed; use `:` or the Clipboard menu to browse it. Copy, Pin/Unpin, Delete and Clear History work through the backend. New captures appear on the next query or reopening history. Paste, Files, Calculator and Shell remain unavailable in service mode. A missing service aborts native app startup with a diagnostic; Pill never starts one or falls back to the embedded backend. Closing Pill leaves the backend running. Fixture mode ignores this environment variable.

Before constructing native services or windows, service-mode Pill calls `maccer_agent_claim_frontend(socket, "pill", error)` and retains the returned guard until application exit. GPUI uses the same per-socket lifetime lock. A duplicate process or an unselected kind exits with a diagnostic; selection is checked even if no frontend is currently running. The additive `maccer_agent_frontend_claim_free` releases the guard. Fixture-native launches and ordinary IPC adapter tests remain unrestricted. Changing backend selection requires quitting old frontends and restarting the backend; no process is killed automatically. Launch through the backend shortcut so Pill receives the service environment, and quit an existing embedded instance first.

Service results include a backend route. Empty-query provider browsing is supported. Escape clears a nonempty scoped query, then returns home on the next Escape; Cmd-P goes home directly. Neither gesture invents a provider prefix. The backend can own the global Maccer shortcut: start it with `--frontend pill --frontend-path "$HOME/pill-macos-spike/build/app/PillSpike.app"`, or set `[service.frontend] kind = "pill"` and `path` to that bundle in its config. It registers `[launcher].hotkey`, shows the connected Pill instance, or launches it with the service socket when absent. Quit an embedded Pill before switching modes. Presentation arrives without a search request ID and opens/refocuses the launcher even after cancellation; it never toggles an already-open launcher closed. Without a backend selection, use `--show-launcher` or the launcher button. Backend reconnection is explicit, so restart the frontend after a service restart. Environment-unset launches still use the separate embedded backend.

Service mode also loads lazy details for the selected result. The bounded preview panel shows plain text, values, metadata, palette swatches and small cache-backed images. Unknown blocks display their fallback text. Cmd-Shift-P toggles it. Selection/query/dismissal changes invalidate old detail replies without consuming search/action request IDs. An expired asset requests one explicit read-only refresh using a fresh request ID; it never retries an action. During a pending query, service-mode rows, cached icons and the preview remain visible while their action/detail authority is revoked immediately, including after search failures. Replacement results remove obsolete previews. Explicit hiding or toggling previews off still clears them. Larger previews are still pending. See [service assets and details](https://github.com/F1lmzy/maccer/blob/main/docs/provider-service-spec.md#assets-and-details).

Shared active theme state arrives through a separate `themeState` event without a request ID. `Maccer.themeState` supplies the shell's semantic colors and active Appearance label even without a search or while the launcher is closed. The service validates `current.json`, retains the last valid palette on read errors, and sends resolved colors without filesystem paths. Pill keeps its existing colors until a palette arrives. Appearance's separate theme catalogs and wallpaper lists are empty, and its Apply/Next/Refresh controls are disabled. Launcher catalog browsing and confirmed Apply use the shared service instead. Embedded `System.theme` remains unchanged when the service environment is unset; native fixtures also remain hermetic. See [shared clipboard and theme state](https://github.com/F1lmzy/maccer/blob/main/docs/provider-service-spec.md#shared-clipboard-and-theme-state).

The searchable launcher also browses the shared service's Themes catalog. Open Themes from home or search by theme name; selection loads resolved palette/metadata details through the same generic preview panel. The service owns helper execution, validation and caching. Pill never reads theme TOML or loads a parallel catalog in service mode. Appearance remains read-only; its empty catalog is separate from launcher browsing. See the [theme operations contract](https://github.com/F1lmzy/maccer/blob/main/docs/shared-service.md#themes-and-action-safety).

When the live service exposes a confirmed Apply, selecting it never applies anything immediately. `Maccer.pendingConfirmation` supplies the descriptor's plain-text prompt, the launcher shows a bounded panel with Apply/Cancel, and only an explicit confirm sends `confirmed: true`. Escape, a query change, a navigation/selection change and any new result snapshot discard the staged consent without sending an operation. The confirm reply keeps the launcher open and active colors still arrive only through `themeState`; Pill never installs the preview palette optimistically. A changed or removed result rejects the confirmation locally. There is no automatic retry. The service allows one in-flight Apply across clients and rejects concurrent attempts. Wallpaper stays unchanged; helper errors warn that changes may be partial. Native desktop Apply acceptance remains pending. See [Apply safety and limitations](https://github.com/F1lmzy/maccer/blob/main/docs/shared-service.md#themes-and-action-safety).

Service-mode tests cover missing-service errors without fallback, fixture isolation from the environment, route tracking, home navigation, rich details, stale selections and recovery against an external fixture service. The launcher C++ and QML suites and the full `scripts/test.sh` suite pass. A running Pill GUI against real service actions still requires interactive verification.

## Build and use

Rust/Cargo and the modified maccer workspace are build-time dependencies. The default source directory is `$HOME/Documents/maccer`. Set `MACCER_SOURCE=/path/to/maccer ./scripts/build.sh` for another checkout. The app bundles `liblauncher_agent.dylib` in Contents/Frameworks and maccer's MIT license. Runtime does not load source files from maccer or start its GPUI binary.

After quitting your older pill instance, run `./scripts/run.sh --show-launcher`. Option-Space or the configured maccer shortcut toggles the launcher. The app-window glyph in the hovered pill opens it without a shortcut. A running standalone maccer may own the shortcut; quit it or change the configuration. Conflicts appear in the launcher footer.

Prefixes and ranking use `~/.config/maccer/config.toml` and maccer's usage SQLite database. The fixed body width is 480 points; maccer's standalone width setting does not resize the QML layout. Apps, files, calculator, web, shell and clipboard copy/actions are available. Paste actions, selected-file previews and file dragging are not wired.

In embedded mode, clipboard history starts capturing while the pill is resident when maccer's clipboard provider is enabled, not only while the launcher is open. In service mode, the backend owns capture and history lasts until that backend exits. It uses the existing 300 ms polling and sensitive-marker filtering. Unmarked passwords can still enter in-memory history. Set `[providers.clipboard] enabled = false` in maccer's config and restart to disable capture. Shell commands execute only on explicit activation and use maccer's existing limits/cancellation. Dismissal cancels cooperative work; it cannot undo actions already performed.

Rendered owned-data panels are saved as `build/screenshots/launcher-shared-web.png` and `launcher-shared-clipboard.png`. Typing regressions cover retained rows/previews, blocked stale actions/details, failed replacements and explicit preview hiding. The full suite passes with 22 launcher C++ and 80 QML cases and no skips.

`./scripts/test.sh` passes the fixture bridge tests, all existing Swift/native tests, QML interactions and relocated Cocoa app self-test. `build/screenshots/launcher.png` records the fixed-size launcher. The relocated native self-test also sends Safari from the real QML field to Rust, checks the returned row, presses Return through Qt and verifies that a safe fixture activation closes the pill. `build/screenshots/launcher-search.png` records that search. Fixture mode uses a hermetic registry and in-memory history and does not read the personal config, clipboard, native icons, register a shortcut or launch applications. Synthetic BGRA icons exercise the owned pixel ABI, QML image provider, warm-query reuse and service teardown; the relocated Cocoa self-test verifies that the actual launcher delegate reaches Image.Ready. The scoped `!fixture` provider supplies harmless output/keep-open outcomes for tests.
